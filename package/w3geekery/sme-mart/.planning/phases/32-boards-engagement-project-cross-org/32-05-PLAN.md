## Key Interfaces and LocalStorage Shape

From 32-PATTERNS.md and design:
```typescript
// PinStorage interface contract.
// load() is async (hydration); getPin/setPin are SYNC off an in-memory Map (template- and CD-friendly).
export interface PinStorage {
  load(): Promise<void>;                   // async hydrate the in-memory Map from backing store; MUST be awaited during init before first render
  getPin(boardId: string): boolean;        // sync read off the hydrated Map
  setPin(boardId: string, isPinned: boolean): void;  // sync Map update + fire-and-forget write-through
  clearPin(boardId: string): void;        // sync Map delete + write-through
  clearAll(): void;                       // sync Map clear + write-through
}

// LocalStorage shape (internal to impl)
// Key: "sme-mart.pins"
// Value: JSON { [boardId: string]: true }
// Example: { "board-uuid-1": true, "board-uuid-2": true }
//
// PKV-swap contract (D-Q10): a future PKV impl makes load() the async network fetch into the Map;
// getPin stays sync off the hydrated Map; setPin does fire-and-forget async write-through internally.
// The swap touches ONLY the impl class — never a call site. ACCEPTED FOUNDATION LIMITATION: setPin
// has no write-confirmation/error-surfacing path (fire-and-forget); a failed PKV write is logged, not
// reported to the user. This is acceptable for pin-state (cosmetic UX preference, no auth/resource impact).
```

```typescript
// Updated engagement-boards-tab.component.ts signature
export class EngagementBoardsTabComponent {
  private readonly pinStorage = inject(PIN_STORAGE_TOKEN);
  readonly boards = signal<Board[]>([]);
  // Gate the pinned/unpinned derivation on hydration so first render reflects persisted state.
  readonly pinsLoaded = signal(false);
  // pinVersion bumps on every setPin so the computed() re-derives off the synchronously-updated Map.
  private readonly pinVersion = signal(0);

  async ngOnInit(): Promise<void> {
    await this.pinStorage.load();     // hydrate the in-memory Map BEFORE first render derivation
    this.pinsLoaded.set(true);
    // ...existing board fetch...
  }

  readonly pinnedBoards = computed(() => {
    this.pinVersion();                // dependency: re-derive after setPin
    return this.pinsLoaded()
      ? this.boards().filter(b => this.pinStorage.getPin(b.id))
      : [];
  });
  readonly unpinnedBoards = computed(() => {
    this.pinVersion();
    return this.pinsLoaded()
      ? this.boards().filter(b => !this.pinStorage.getPin(b.id))
      : this.boards();
  });
  readonly displayBoards = computed(() => [...this.pinnedBoards(), ...this.unpinnedBoards()]);

  onPinToggle(board: Board): void {
    this.pinStorage.setPin(board.id, !this.pinStorage.getPin(board.id)); // sync Map update + fire-and-forget write-through
    this.pinVersion.update(v => v + 1); // trigger pinned/unpinned re-derivation (Map mutation is not signal-tracked)
  }
}
```

Note: because `getPin()` reads a plain `Map` (not a signal), the `pinned/unpinned` computed()s cannot depend on it directly — bump an explicit `pinVersion` signal on each `setPin` to drive re-derivation. The `pinsLoaded` gate ensures the very first render (before `load()` resolves) does not derive against an empty Map and flash unpinned state.

```typescript
import { InjectionToken } from '@angular/core';

/**
 * Pin storage contract for persisting board pin state.
 *
 * Implementations may use localStorage now, or PKV / backend storage later.
 * This interface enables the localStorage → PKV swap (D-Q10) with ZERO call-site changes:
 * load() carries the only async cost (network fetch in the PKV impl); getPin/setPin stay sync.
 *
 * Hydration model: load() fills an in-memory Map. getPin reads that Map synchronously (template-
 * and change-detection-friendly). setPin updates the Map synchronously then does fire-and-forget
 * write-through to the backing store (no signature change across impls).
 */
export interface PinStorage {
  /**
   * Hydrate the in-memory pin cache from the backing store.
   * MUST be awaited during component init BEFORE deriving pinned/unpinned arrays for first render.
   * localStorage impl: sync read into the Map wrapped in Promise.resolve(). PKV impl: async network fetch.
   */
  load(): Promise<void>;

  /** Get pin state for a board (sync read off the hydrated Map). @returns true if pinned. */
  getPin(boardId: string): boolean;

  /** Set pin state (sync Map update + fire-and-forget write-through to backing store). */
  setPin(boardId: string, isPinned: boolean): void;

  /** Clear pin state for one board (sync Map delete + write-through). */
  clearPin(boardId: string): void;

  /** Clear all pin state (sync Map clear + write-through). */
  clearAll(): void;
}

export const PIN_STORAGE_TOKEN = new InjectionToken<PinStorage>('PIN_STORAGE');
```

Keep the file concise (interface + token + doc comments). No implementation details. getPin/setPin are synchronous (in-memory Map); load() is the only async member, isolating the future PKV network cost behind a single awaited init call.

```typescript
import { Injectable } from '@angular/core';
import { PinStorage } from './pin-storage.interface';

const STORAGE_KEY = 'sme-mart.pins';

/**
 * localStorage-backed pin storage.
 * Source of truth is an in-memory Map (sync reads); localStorage is the persistence layer.
 * Data shape on disk: { [boardId]: true } (only truthy values stored to save space).
 */
@Injectable({
  providedIn: 'root'
})
export class LocalStoragePinStorage implements PinStorage {
  private pins: Map<string, boolean> = new Map();

  // Async member by contract; localStorage read is sync, so we just resolve.
  // The PKV impl replaces this body with an async network fetch into the same Map.
  load(): Promise<void> {
    try {
      const stored = localStorage.getItem(STORAGE_KEY);
      if (stored) {
        const data = JSON.parse(stored) as Record<string, boolean>;
        this.pins = new Map(Object.entries(data));
      }
    } catch (e) {
      // Corrupt/disabled storage: start empty rather than crash hydration.
      console.warn('PinStorage.load failed; starting with empty pin set:', e);
      this.pins = new Map();
    }
    return Promise.resolve();
  }

  getPin(boardId: string): boolean {
    return this.pins.get(boardId) ?? false;
  }

  setPin(boardId: string, isPinned: boolean): void {
    if (isPinned) {
      this.pins.set(boardId, true);
    } else {
      this.pins.delete(boardId);
    }
    this.writeThrough(); // fire-and-forget; sync for localStorage, async (unawaited) for PKV
  }

  clearPin(boardId: string): void {
    this.pins.delete(boardId);
    this.writeThrough();
  }

  clearAll(): void {
    this.pins.clear();
    this.writeThrough();
  }

  // Fire-and-forget write-through. No write-confirmation surfaced to callers — see PKV-swap note.
  private writeThrough(): void {
    try {
      const data = Object.fromEntries(this.pins);
      localStorage.setItem(STORAGE_KEY, JSON.stringify(data));
    } catch (e) {
      // Quota exceeded / private mode: log, do not surface. Pin state is cosmetic.
      console.error('PinStorage.writeThrough failed (pin state not persisted):', e);
    }
  }
}
```

Key points:
- `@Injectable({ providedIn: 'root' })` enables DI without explicit registration
- In-memory Map is the source of truth → `getPin` is sync (template- and CD-friendly)
- `load()` hydrates the Map; for localStorage it is sync-then-`Promise.resolve()`; callers MUST await it before first-render derivation
- `setPin`/`clearPin`/`clearAll` mutate the Map synchronously then fire-and-forget `writeThrough()`
- Silent/logged catch on localStorage errors (quota exceeded, disabled in private mode)
- STORAGE_KEY = 'sme-mart.pins' (SME Mart specific, avoids collisions)

**PKV swap (D-Q10), ACCEPTED FOUNDATION LIMITATION:** a future PKV impl makes `load()` the async network fetch into the Map; `getPin` stays sync off the hydrated Map; `setPin` does fire-and-forget async write-through (no signature change). The swap touches ONLY this class — never a call site. The trade-off is that `setPin` has **no write-confirmation/error path** to the user (a failed PKV write is logged, not reported). Accepted because pin state is cosmetic (UX preference; no auth/resource impact). Server never relies on pin state.
