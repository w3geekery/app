## Locked decisions
- **D-34:** Vetting Board name = "Vetting Board" (exact, locked)
- **D-35:** Vetting Board description = "Vetting items for {engagement.name}" (exact template, locked)
- **D-04:** Board governance model: ownerId = engagement.id (not org), scoped to engagement
- **Provisioner Step D:** Create vetting Board via `platformClient.getProjectApi().createBoard()` with ownerId=engagement.id

## Platform.Board API expectations
- **Board creation:** Returns BoardExtended with id, name, description, ownerId
- **Task on Board:** Task created with `boardId` parameter (SDK term) or similar
- **Task hierarchy:** Task.parentTaskId = vetting Task (subtask); parent Task.id = engagement-related Task (if exists)
- **Rendering:** SME Mart Vetting view queries Board + tasks via `platformClient.getBoardApi().listTasks()` or similar

## Risk mitigations
- If Board creation succeeds but is not queryable → backlog entry [VETTING-BOARD-RENDERING] Phase 32
- If Task hierarchy breaks (parent link missing) → backlog entry, same
- If Board ownerId is wrong (org instead of engagement) → backlog entry for governance model revision
