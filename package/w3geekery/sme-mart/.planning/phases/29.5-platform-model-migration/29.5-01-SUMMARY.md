## Key Findings

### High-Risk Refactoring (Plans 02-04)

**Highest touch:** `engagements.service.ts` (81 Engagement refs, 11 GQL calls)
- Method targets: listEngagements, searchEngagements, getEngagement, getEngagementRaw
- Field mapping mismatch: GqlEngagementResponse → ProjectExtended (ownerId, memberCount, boardCount, tag object)
- 15+ specs depend on this service; ZerobiasClientSessionId stub required (per PATTERNS.md)

**Second highest:** `sme-mart-project.service.ts` (42 SmeMartProject refs)
- Method targets: createProject (Pipeline.receive → platformClient.create), getProject, listProjects, updateProject
- Field mapping: SME_MART_PROJECT_FIELD_MAPPING obsolete for platform reads (keep for GQL legacy fallback)
- Touch-It-Fix-It: likely has pre-Phase-27.5 constructor patterns; modernize to inject() on modification

**Vetting rewrite:** `vetting.service.ts` (31 EngagementVettingItem refs)
- Migration: GQL EngagementVettingItem → platform.Task (paired-task shape per D-12)
- Lazy-create vetting Board on first vetting item (not in provisioner recipe per D-11)
- Paired-task pattern: parent + subtask per side; subtasks inherit boardId from parent via server-default chain

### Open Question for Plan Implementation

**D-23 member-filter param name** — exact parameter for filtering by member in both `platform.Project.list` and `portal.Project.search` is TBD. Candidates: `memberPrincipalId`, `memberFilter`, `member`. **Recommendation:** Run live `zerobias_describe` on both endpoints before Plan 03 engagements.service.ts refactor to confirm exact param name and type.
