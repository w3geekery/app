**D-23 Resolution (Plan 03 Task 0 findings, `7960daf` + appended to `INVENTORY.md`):**

Neither `platform.Project.list` nor `portal.Project.search` exposes a member-filter parameter.

- **`platform.Project.list` signature** (SDK `@zerobias-com/platform-sdk@1.1.19`):
  ```
  list(pageNumber?, pageSize?, boundaryId?, ownerId?, status?, visibility?, sort?, pageToken?)
  ```
  Scope params are `boundaryId` and `ownerId`. **No** `memberPrincipalId`, `memberFilter`, `member`, or similar surface.

- **`portal.Project.search` signature** (SDK `@zerobias-com/portal-sdk@1.1.19`):
  ```
  search(searchProjectBody, pageNumber?, pageSize?, sort?, pageToken?)
  ```
  `SearchProjectBody` exposes `search` / `name` / `description` / `ownerIds[]` / `boundaryIds[]`. **No** member-filter field.

**Implication:** Provider-side "My Engagements" filtering cannot be a single platform/portal call. Either (a) N+1 pattern (list projects, then `listMembers(projectId)` per project, filter by principal), or (b) a new API surface added platform-side. Deferred to v1.5 backlog. The Plan 01 success criterion ("Member-filter param shape confirmed") is partial-meet (the *absence* of the param is now confirmed); tracked as **DEVIATION-29.5-01-D23**.

### DEVIATION-29.5-02-V3 — Plan 02 v3 rewrite post-close

**Reason:** Plan 02 closed 2026-05-11 with a structurally-correct 5-step recipe. UAT walkthrough 2026-05-12 (and decisions D-46, D-48, D-50 ratified the same day) revealed four corrections that the merged recipe lacked:

1. **Depth-2 tier identity missing.** Step D created a tagless child (`tagId: undefined`), so the depth-2 "Project tier" was not hydra-queryable as a distinct tier.
2. **Tier label mis-named "Workspace".** Per D-50 canonical tier mapping (Brian's sketch, ratified 2026-05-12), depth 2 is the **Project** tier — FIXED, NOT "Workspace". Workspace/Aperture/Thread are RENAMEABLE depth-3+ middle tiers NOT instantiated by v1.4. Constants, methods, return-field names all carried the wrong label.
3. **Redundant Steps F + G.** UAT empirical validation 2026-05-12 confirmed `platform.Project.create` auto-creates a default Board (named `"{projectName} Board"`) and auto-assigns the creator as Project Lead. D-48 establishes that Lead inherits down the parentId chain. Steps F (`ensureDefaultBoard`) and G (`ensureProjectMember`) are no-ops obviated by these auto-behaviors.
4. **Boundary-scope policy unstated in code.** Engagement Project is intentionally org-level (`boundaryId` omitted) per `ENGAGEMENT-BOUNDARY-SCOPE-REVISIT-1`. The merged code already omitted `boundaryId`; the v3 amendment adds JSDoc and a spec assertion to lock that intent.

**Resolution commit:** `523e924`. Recipe is now 3 SDK creates per provisioning (A, C, D). Spec coverage 14/14 passing (was 16/16; F + G tests removed).

**ci/prod follow-up:** `SME_MART_TIER_PROJECT_TAG_ID` is hardcoded to the UAT UUID (`420b0753-e72c-4b81-8929-70508a119bf0`). ci/prod tier-tags must be bootstrapped before this recipe runs in those environments. Backlog item **TIER-TAG-ENV-BOOTSTRAP-1** filed (see below).
