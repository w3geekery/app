## Locked decisions
- **D-08:** Engagement Task (Step B in provisioner recipe) is dropped — definitive. No fallback to ZB UI rendering.
- **D-04:** platform.Project governance model: ownerId=buyerOrg, parentId=null on engagement; workspace Project has parentId=engagement.id
- **D-45:** 3P verification gates may NOT depend on ZB internal UI surfaces (Governance, Task UI, etc.). Verification happens at SDK contract layer + SME Mart's own UI.
- **Provisioner output (Plan 02):** Steps A/C/D/F/G create: hydra Tag + engagement Project + workspace Project + vetting Board + identity tag wiring; Step B (Engagement Task) is NOT created.

## Platform.Project SDK contract expectations
- **Create:** `platform.Project.create` returns ProjectExtended with id, name, description, ownerId, parentId, tagId
- **Get:** `platform.Project.get(id)` returns the same shape as create returned (no field drift)
- **List by parent:** `platform.Project.list` filtered by `parentId=<engagement.id>` returns the workspace child Project
- **Timing:** Synchronous within the same SDK session (no async delay before reads)

## SME Mart UI integration expectations
- After provisioning, SME Mart's engagement list page surfaces the new engagement (engagements.service queries platform.Project + post-filters per demo-visibility rules per Plan 03)
- Engagement detail navigates from the list correctly
- Optional: future SME Mart admin page can surface raw platform.Project + platform.Board for ops troubleshooting; not v1.4 scope (captured as backlog item SME-MART-PLATFORM-ADMIN-PAGE-1, lazy-evaluated)

## Failure handling
- If `platform.Project.create` fails → Plan 02 bug; fix in Plan 02, do NOT reinstate Engagement Task
- If `platform.Project.get` returns different shape than create returned → Plan 02 bug OR SDK bug (file SDK issue with Kevin); fix in place
- If SME Mart engagement list doesn't surface the new engagement → engagements.service bug from Plan 03; fix Plan 03, do NOT reinstate Engagement Task
- In all failure cases, D-08 stays dropped — failures are bugs in our own work, not justifications for resurrecting deprecated platform concepts.
