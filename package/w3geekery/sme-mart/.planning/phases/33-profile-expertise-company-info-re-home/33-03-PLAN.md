Implement the 13 Half-B mutation methods in provider-profiles.service.ts using the write pattern from PATTERNS.md and RESEARCH.md §1.2. The file stubs are currently throwing "not yet implemented"; replace each stub with a full implementation.

**⚠ Pipeline.receive is FULL-REPLACE (Director note 2026-06-26).** A `pushEntity` write **nulls every field not present in the payload** — partial updates silently wipe omitted fields. The `pipeline-write.service.ts` write-through cache+merge mitigates this, but ONLY if the cache is warm. Rule for every write method below: send the **complete** object (all current field values), or read-merge the existing record into the payload before writing — never a sparse patch. This is the one real footgun (the prior "fire-and-forget silent failure" was already remediated under FF-03 — failures re-throw). Applies to `updateProfile` especially (don't blank `tagline`/`website`/etc. when only `employeeCount` changed).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|

| Service → Pipeline | Writes via PipelineWriteService; class IDs must resolve (validated in Wave 0) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33-06 | Authorization | Half-B write methods | mitigate | All writes are org-scoped via orgId FK (not provider_id). Component must supply the caller's orgId; service does not validate ownership (guard gate at component mount). Once orgId is supplied, the write is scoped to that org. No cross-org write possible without passing a different orgId. |
| T-33-07 | Injection (ID-space mismatch) | ProviderServiceSegment writes | mitigate | serviceSegmentId must be a Catalog Service-segment UUID (Catalog FK). If the resolver supplies a hydra tag ID or other ID space, the write succeeds but reads fail (FK mismatch). D-56 locks the use of real Catalog Service segments (133 leaf nodes). Component/form must validate that the ID is a Catalog Service-segment before passing to addServiceSegment. |
| T-33-08 | Denial of Service | Batch writes (updateProfile + Address) | accept | updateProfile may write 2 entities (OrgProfile + Address). If the Address write fails mid-batch, OrgProfile is persisted but Address is not (no transaction). This is acceptable for v1; full transactional batching is future work. Error message surfaces to user. |

</threat_model>
