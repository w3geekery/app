# GSD 1.38.5 — SDK state-frontmatter writes corrupt STATE.md + per-project config migration gap

Four distinct bugs surfaced during Phase 29.5 insert-phase + discuss-phase + plan-phase. All trace to GSD 1.38.5 (installed 2026-04-30 via the 1.30.0 → 1.38.5 update).

## Bug 1 — `gsd-tools state patch` corrupts STATE.md frontmatter

**Status:** OPEN (workaround documented)

`node ~/.claude/get-shit-done/bin/gsd-tools.cjs state patch --current_phase 29.5` corrupts `STATE.md` frontmatter:
- `milestone_name` field is rewritten to the literal string `"milestone"`
- `current_phase` field is dropped entirely

**Reproduced:** Phase 29.5 insert-phase agent ran the SDK patch command per the workflow doc; STATE.md frontmatter became unusable; reverted via `git checkout STATE.md` and applied the edit by hand.

**Workaround:** Direct frontmatter edits on STATE.md; never invoke `gsd-tools state patch` for `current_phase` writes in 1.38.5.

## Bug 2 — `gsd-tools state record-session` corrupts STATE.md frontmatter

**Status:** OPEN (workaround documented)

Same corruption pattern as Bug 1. Different SDK entry point; same root cause inside GSD's STATE.md write logic.

**Reproduced:** Phase 29.5 discuss-phase agent ran `state record-session` despite the warning from Bug 1; same corruption manifested; reverted via `git checkout` and patched manually.

**Workaround:** Avoid all SDK state-frontmatter writes in 1.38.5; direct file edits only. Treat `gsd-tools state {patch,record-session}` as broken in this version.

## Bug 3 — `state.add-roadmap-evolution` workflow handler missing

**Status:** OPEN (workaround documented)

The insert-phase workflow calls a `state.add-roadmap-evolution` handler to append entries to STATE.md's `### Roadmap Evolution` section. The handler doesn't exist in GSD 1.38.5; invocation fails silently or with handler-not-found error.

**Workaround:** Direct edit of STATE.md's existing `### Roadmap Evolution` section to append the new phase entry. Documented in Phase 29.5 insert-phase agent's deviation notes.

## Bug 4 — Per-project config migration gap (workflow.* keys absent)

**Status:** FIXED 2026-05-08 (.planning/config.json backfilled)

The 2026-04-30 GSD update bumped code 1.30.0 → 1.38.5 but did NOT run a per-project config-backfill step. New workflow keys introduced in 1.38.5 (`discuss_mode`, `ui_phase`, `ui_safety_gate`, `pattern_mapper`, `security_enforcement`, `ai_integration_phase`, `node_repair`, `post_planning_gaps`, plus 16 others) were absent from `.planning/config.json`. Calling `gsd-tools config-get workflow.<key>` on absent keys emits `Error: Key not found:` to stderr with exit code 1.

Workflow scripts use `|| echo "true"` shell fallbacks for most reads, so missing keys don't actually block — but the noise is alarming and caused defensive stops during plan-phase.

**Reproduced (illustrative, not exhaustive):**
- `workflow.discuss_mode` missing → discuss-phase config-get fails (caught 2026-05-08 evening; patched in commit `60057dc`)
- `workflow.security_enforcement`, `workflow.pattern_mapper`, `workflow.ui_safety_gate`, `workflow.ui_phase` missing → plan-phase emitted 4 errors in sequence (caught 2026-05-08 night)

**Root cause:** Per-project `.planning/config.json` is independent state. The GSD update touches binaries and workflow definitions but doesn't migrate per-project configs. Defaults are coded in `~/.claude/get-shit-done/bin/lib/config.cjs:99-127` + `core.cjs:242-270` but `config-get` itself doesn't fall back to those defaults — it strictly reads from the on-disk JSON.

**Fix applied:** `.planning/config.json` backfilled to include all 27 canonical workflow keys with their 1.38.5 defaults. Commits `60057dc` (`discuss_mode` patch) + `62cecad` (full 24-key backfill).

**Recommended platform-side fix (for future GSD versions):** Migration script should diff each `.planning/config.json` against the current template and append missing keys with their defaults. Could be invoked automatically by `/gsd-update` or surfaced as `gsd-tools config migrate` for opt-in repair.

## Detection rule for future Director sessions

If `gsd-tools config-get workflow.<key>` emits `Error: Key not found:`, the key is absent from `.planning/config.json` — NOT necessarily a real bug. Workflow scripts almost always have `|| echo "true"` fallbacks. Patch the config with the canonical default from `~/.claude/get-shit-done/bin/lib/config.cjs:99-127` to silence the noise.

If `gsd-tools state {patch,record-session}` is about to run, ABORT and use direct frontmatter edits. Bugs 1 + 2 are unpatched; SDK state-frontmatter writes will corrupt STATE.md.
