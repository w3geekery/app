# Errata 035 — GSD 1.41.2 `/gsd-plan-phase` Aftermath: commit_docs Ignored + STATE.md Corruption + PATTERNS.md Untracked

**Date:** 2026-05-12 (Phase 30 planning, GSD 1.41.2 first use)
**Severity:** Medium — multiple drift modes, all caught at Director review, fixed in one cleanup commit
**Type:** Upstream GSD tool behavior — same class as 029 (1.38.5 state-frontmatter bugs)
**Phase:** 30

## What happened

After `/gsd-plan-phase 30 --skip-research` ran successfully (5 plans, 3 waves, all gates green per plan-checker iteration 2/3), the orchestrating agent reported:

> "Plans NOT auto-committed (commit_docs=false). Director may review with git diff / git add before flipping into execute."

That status was wrong in **three** distinct ways:

### 1. `commit_docs=false` was ignored — round-1 plans WERE auto-committed

Despite the project's GSD config setting `commit_docs: false` (verified via `gsd-sdk query init.plan-phase 30` → `"commit_docs": false`), the workflow auto-committed plans twice:

- `0e7ab8e` "docs(phase-30): create 5-plan set for default board + coming-soon placeholders" — five PLAN.md files added
- `d51190e` "docs(30): update ROADMAP.md with Phase 30 planning completion" — ROADMAP.md updated

These commits landed silently; the agent's "NOT auto-committed" claim contradicts what git shows.

### 2. Plan-checker round-2 fixes were stranded as uncommitted modifications

Plan-checker iteration 1 caught **2 BLOCKERs** + **4 WARNINGs**:

- BLOCKER 1: stale `PB-05` reference in 30-03 and 30-05 (PB-05 is not a Phase 30 requirement)
- BLOCKER 2: PB-03 + PB-04 missing from 30-03 (FeatureComingSoonComponent coverage)
- 4 WARNINGs about "user-observable truths" rewording, G5 defensive copy verbatim, G6 `wc -l` gate, PATTERNS.md analog citation

Iteration 2 of the agent's revision loop applied all six fixes in the working tree — but did NOT amend or follow-up-commit those changes. So commit `0e7ab8e` on `origin` contains the **pre-fix** plans (with `PB-05` stale refs and missing PB-03/PB-04 coverage); the round-2 fixes sat as uncommitted `M` entries until Director caught them.

If Director had advanced to execute without checking `git diff`, the executor would have read the broken committed plans, NOT the corrected working-tree versions (depending on which file state the execute workflow reads — typically committed). Either way: divergence between "what plan-checker approved" and "what's in git history" is unacceptable.

### 3. STATE.md corrupted: `milestone_name` overwritten with literal placeholder string `"milestone"`

The workflow rewrote `STATE.md` frontmatter, replacing:

```yaml
milestone_name: 3P Onboarding & Default Engagement
```

with:

```yaml
milestone_name: milestone
```

That's the workflow template's placeholder variable name leaking through as a string literal — same class of bug as errata 029's state-frontmatter issues from 1.38.5. The progress numbers (21/12 phases, 68/60 plans) and `last_updated` timestamp were also rewritten; those values are net-correct given 29.5 is closed, but the `milestone_name` regression is a real bug.

### 4. PATTERNS.md left untracked

`30-PATTERNS.md` (818 lines, produced by pattern-mapper agent as the planner's input) was created but never `git add`ed by the workflow. Showed up as `??` in `git status` after the workflow returned.

## Fix

Single Director cleanup commit `5ba9926`:

- Applied round-2 plan revisions to all 5 PLAN.md files
- Added `30-PATTERNS.md` to git
- Restored `STATE.md` `milestone_name` to "3P Onboarding & Default Engagement" (kept the corrected progress numbers + timestamp)

## Carry-forward for next Director session

When dispatching `/gsd-plan-phase` in GSD 1.41.2, expect this aftermath pattern:

1. Run `git log --oneline` after the workflow returns — confirm whether plans were auto-committed despite `commit_docs=false`.
2. Run `git status -sb` — check for: (a) modified PLAN.md files that should have been amended into the auto-commit, (b) untracked PATTERNS.md, (c) modified STATE.md.
3. Run `git diff .planning/STATE.md` — look for `milestone_name: milestone` regression. Restore manually.
4. Batch the cleanup as a single `docs(director,NN): clean up planner aftermath ...` commit before dispatching execute.

When this is fixed upstream (or when GSD ships a new version that respects `commit_docs=false` and doesn't corrupt STATE.md), flip status to `superseded` and note the version that fixed it.
