## 2. Make changes

**Per-package layout** (under `package/w3geekery/smemart/`):
- `classes/` — AuditgraphDB class YAMLs (PascalCase filenames)
- `interfaces/` — shared property contracts (PascalCase)
- `fields/` — atomic field definitions (camelCase dot-notation: `className.fieldName.yml`)
- `enums/` — enum values (ALL_CAPS values, see rules below)
- `documents/` — document type definitions (optional)
- `catalog.yml` — package catalog entry
- `package.json` — npm package definition (`@zerobias-org/schema-w3geekery-smemart`)
- `build.gradle.kts` — one-liner: `plugins { id("zb.schema") }`
- `gate-stamp.json` — **committed**; preflight rejects packages without one. Regenerated by `zbb gate`.

### Adding a field to a class

1. Add the property to the class YAML:
   ```yaml
   - myField:
     field: className.myField
   ```

2. Create the field definition at `fields/className.myField.yml`:
   ```yaml
   description: 'What this field is'
   displayName: 'My Field'
   type: string
   ```
   Types: `string`, `number`, `boolean`, `date`. Add `multi: true` for arrays.

### Adding a link between classes

```yaml
# In ClassA.yml — single link to ClassB
- classB:
  linkTo: ClassB.id.classAs

# In ClassB.yml — reverse multi-link back to ClassA
- classAs:
  linkTo: ClassA.id.classB
  multi: true
```

Both sides of the link must be defined. Format is `ClassName.id.reversePropertyName`.

### Important YAML rules

- `linkTo` must be at **SIBLING indent level** (same level as the property key), NOT nested. The validate script does NOT catch nested linkTo; the dataloader does.
- **Cannot `linkTo` platform-native entities** (Boundary, Task) — they're hydra entities, not schema classes. Use scalar fields instead (`boundaryId: { field: x.boundaryId }`).
- **Enum values MUST be ALL_CAPS** matching `[A-Z][A-Z0-9_]*`. Examples: `ACTIVE`, `IN_PROGRESS`, `NOT_APPLICABLE`. The validate script does NOT enforce this; the dataloader rejects at load time.
- **Missing imports trip the dataloader.** Extending `Object`, `File`, `Element` requires the providing package listed in `zerobias.imports` (typically `zerobias.zerobias.platform.schema` and/or `zerobias.zerobias.base.schema`).
- **GQL auto-strips `Id` suffix on link field names.** Pipeline push data must use the link name (e.g., `engagement` not `engagementId`). Scalar fields keep their declared name.

## 3. Validate with `zbb gate` (MANDATORY)

**`npm run validate` alone is NOT sufficient.** It only checks package structure. The real validation runs the dataloader against a scratch DB. `zbb gate` is the canonical entry point — it chains everything.

### ⚠️ RE-RUN AFTER ANY CHANGE — NO EXCEPTIONS

Cherry-picks, rebases, amends, squashes — **ANY time the commit content changes, re-run the full gate from Step 3.** A previous validation is INVALID after modifying commits.

> **Incident 2026-04-06:** Cherry-picked a commit adding `profileItemId` to a class without its field YAML. Skipped re-validation because "we already ran it." Broke prod/UAT dataloader for 60+ minutes.

### Step 1: Update dataloader to latest (REQUIRED)

**ALWAYS update dataloader before every validation run.** This is not optional. CI uses the latest version — older local versions may be more lenient and pass schemas that fail on CI. We learned this the hard way: v1.0.89 accepted nested `field:` indent that v1.0.92 correctly rejected.

```bash
npm install -g @zerobias-com/platform-dataloader@latest
dataloader --version 2>&1 | grep "Dataloader v"
```

### Step 2: Ensure scratch DB is running

```bash
docker ps --filter name=supabase-pg-content-dev
```

If not running (e.g., after reboot):
```bash
docker start supabase-pg-content-dev
```

If the container doesn't exist at all (first-time setup only):
```bash
npx @zerobias-org/util-content-dev-schema
```

### Step 3: Export scratch-DB env vars

```bash
export PGHOST=localhost
export PGPORT=15432
export PGUSER=postgres
export PGPASSWORD=welcome
export PGDATABASE=content_dev
export PGSSLMODE=disable
```

These match the Supabase scratch container (PG17). CI uses different values (Neon branch, PG15/16, port 5432, SSL required) — that's intentional; local is a fast smoke test, CI is the authoritative gate.

### Step 4: Run `zbb gate`

From the repo root:

```bash
cd ~/Projects/w3geekery/zb-forks/org/schema
zbb gate
```

This chains: `validate` → `lint` → `compile` → `test*` → `buildArtifacts` → `testIntegrationDataloader` → `writeGateStamp`. Without `NEON_API_KEY` / `NEON_PROJECT_ID` in env, `testIntegrationDataloader` is **skipped** (not failed) and the stamp still gets written.

For a single package only (faster):
```bash
./gradlew :w3geekery:smemart:gate
```
This is the underlying gradle invocation — same effect as `zbb gate` scoped to one package. Use it when iterating.

For the older manual dataloader path (rarely needed; the gate task includes this):
```bash
cd package/w3geekery/smemart
dataloader --content-dev --skip-pgboss --skip-dynamo -d ./
```

Must exit with code 0 and print "Importer finished successfully".

### Step 5: Verify gate-stamp.json was updated

```bash
git diff package/w3geekery/smemart/gate-stamp.json
```

The stamp should reflect a new `sourceHash`. **Commit the stamp** alongside the schema changes. PRs without an updated stamp fail upstream preflight.

### Step 6: Touch the local validation marker

```bash
touch .dataloader-validated
```

**ONLY touch this AFTER gate succeeds.** The SME Mart app-side Claude hook checks this marker's age (must be < 30 min). Never touch it without actually running gate.

## 4. Commit

```bash
cd ~/Projects/w3geekery/zb-forks/org/schema

git add package/w3geekery/smemart/classes/<changed>.yml
git add package/w3geekery/smemart/fields/<new-or-changed>.yml
git add package/w3geekery/smemart/gate-stamp.json    # ALWAYS include stamp
# Do NOT add .dataloader-validated or .scratch-db/

git commit -m "feat(w3geekery): <description>"
```

**Commit message conventions:**
- Use Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`).
- Scope to the package: `feat(w3geekery):` or `fix(w3geekery):`.
- **Do NOT auto-append `Session: claude --resume <branch>` lines.** Session names aren't aliased to branches and the resulting `claude --resume` link is broken for anyone who tries it. (Memex: `feedback_no_session_resume_fabrication`.)

The Claude hook lives in the **app** repo (not the schema repo) but guards schema commands:
`~/Projects/w3geekery/zerobias-org-forks/app/.claude/hooks/check-git-workflow.sh`

It verifies:
- You're in the w3geekery fork at `~/Projects/w3geekery/zb-forks/org/schema` (NOT `~/Projects/zb/`)
- You're synced with `upstream/main`
- Dataloader marker exists and is fresh (< 30 min)
- New `field:` properties have corresponding field definition YAMLs

> **Hook path note:** the hook may still hardcode the older `zerobias-org-forks/schema` path. Schema-fork-side commits hand-driven by Clark + Director are the canonical workflow per memex `Schema-repo PRs are Clark + Director hands-on`; agents commit locally but never push/PR.

## 6. Create cross-fork PR (Clark + Director hands-on)

```bash
gh pr create \
  --repo zerobias-org/schema \
  --base main \
  --head w3geekery:feat/<branch-name> \
  --title "feat(w3geekery): <description>" \
  --body "$(cat <<'EOF'
## Summary
- bullet points of changes

## Validation
`zbb gate` exit 0 (dataloader v<version>, gate-stamp.json refreshed).

## Test plan
- [x] `zbb gate` exit 0 against local Supabase scratch (PG17)
- [x] gate-stamp.json committed with refreshed sourceHash
- [ ] CI dataloader on PR `approved` label (maintainer-gated)

🤖 Generated with [Claude Code](https://claude.com/claude-code)
EOF
)"
```

**Critical flags:**
- `--repo zerobias-org/schema` (upstream, NOT the fork — without this, `gh` defaults to the fork and the PR never reaches upstream)
- `--base main` (NOT `dev` — see "What changed recently" above)
- `--head w3geekery:feat/<branch>` (cross-fork reference)

**The `approved` label gate:** Upstream CI's dataloader job is **skipped** until a maintainer (Daniel Rojas owns Content) adds the `approved` label. A skipped CI check is **NOT a pass** — treat it as "did not run." Watch the `Test` check on the PR:

| Status | Meaning |
|---|---|
| `Test` green / success | Dataloader ran against a Neon branch and passed. Safe to merge. |
| `Test` red / failure | Dataloader ran and failed. Read logs and fix. |
| `Test` skipped or absent | Dataloader did NOT run. NOT a pass. Wait for label or push an empty commit (`git commit --allow-empty -m "ci: trigger"`) after label is added to force `synchronize`. |

## 7. After merge

- GQL schema reloads every ~15 minutes after merge to main.
- New fields won't be queryable until the reload completes.
- **Class IDs are deterministic** (UUID v5 from YAML content) — same across local/CI/prod.
- **Pipeline IDs are per-environment** (NOT deterministic).
- The TypeScript twin package (`-ts` companion) is auto-generated by `@zerobias-com/platform-schema-ts-generator` against the schema loaded into an ephemeral Neon Postgres branch and published by the bundle/publish workflow.
- The aggregate `@zerobias-org/schema-bundle` package is auto-refreshed by the publish workflow.

## GQL field name gotchas

| YAML | GQL query field | Pipeline push field | Notes |
|------|----------------|--------------------|----|
| `field: x.myField` | `myField` | `myField` | Scalar — name matches |
| `linkTo: Other.id.reverse` | `other { id name }` | `other` (just the ID string) | Link — needs `{ subfields }` in query, bare ID in push |
| Base class dates | `dateCreated`, `dateLastModified` | Auto-set by platform | NOT `createdAt`/`updatedAt` |

## Three validation layers (per upstream CONTRIBUTING.md)

| Layer | Command | What it checks | Speed | Required before push? |
|---|---|---|---|---|
| 1. Package structure | `npm run validate` | `package.json` shape, `catalog.yml` shape, `.npmrc` presence, naming consistency | seconds | Yes (also runs inside `zbb gate`) |
| 2. Local dataloader (gate) | `zbb gate` | Field references, `linkTo` targets, bidirectional links, enum casing, type matches, imports | ~30s–2m | **Yes** |
| 3. CI dataloader | Triggered by maintainer adding `approved` label | Same dataloader, against a Neon branch cloned from `content-master` with production-shape data | minutes | Triggered for you; cannot run locally |

Layer 1 alone lets real bugs through. Layer 2 is the smallest local check that catches what production cares about. Layer 3 is authoritative but maintainer-gated.

## Common failure modes

1. **Class references a field with no `fields/*.yml`** — dataloader: `field "engagement.budgetType" not found`. Create the missing field YAML or remove the reference.
2. **`linkTo` points to undefined class** — dataloader: `unknown class "Foo"`. Confirm target exists in your `classes/` or in a package listed in `zerobias.imports`.
3. **Bidirectional link defined only on one side** — dataloader complains about missing inverse OR the link silently fails to materialize. Define both sides.
4. **Lowercase enum values** — dataloader: `value "active" does not match [A-Z][A-Z0-9_]*`. Rename to ALL_CAPS.
5. **Missing `zerobias.imports` entry** — dataloader can't resolve base classes. Add the providing package's catalog name.
